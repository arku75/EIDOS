> producto competidor. El fork solo se permite para evaluar y contribuir.

## Reglas obligatorias para contribuir (ESSL §4 y §5)

Al hacer cualquier cambio, propuesta o derivado, **estás obligado** a:

1. **Documentar TODO cambio o propuesta** en el archivo `THIRD_PARTY_CHANGES.md`,
   indicando: autor/identidad, fecha, archivos/áreas afectadas, descripción
   completa y propósito. Sin esta documentación, el cambio incumple la licencia.
2. **Conservar** en toda copia o derivado el copyright original, la licencia y la
   atribución a SER y a EIDOS.
3. **Comunicar por escrito a SER** (vía Pull Request o `anio1996991@gmail.com`)
   cada cambio documentado **antes** de cualquier uso más allá de la evaluación
   local.
4. **No presentar** EIDOS, un derivado, ni ninguna idea derivada como creación
   propia.

> 🔐 **Cesión de derechos (ESSL §5):** toda contribución, cambio, idea o propuesta
> que envíes queda **cedida de forma exclusiva e irrevocable a SER**, con todos
> sus derechos de propiedad intelectual. SER puede usarla, modificarla,
> relicenciarla y comercializarla sin compensación ni atribución. Si no aceptas
> estas condiciones, no contribuyas.

## Cómo empezar

1. Fork el repositorio (**solo para evaluación/contribución**, ver LICENSE)
2. Crea una rama: `git checkout -b feature/tu-cambio`
3. Haz tus cambios
4. **Registra cada cambio en `THIRD_PARTY_CHANGES.md`** (obligatorio)
5. Commit: `git commit -m "Descripción clara"`
6. Push: `git push origin feature/tu-cambio`
7. Abre un Pull Request comunicando los cambios a SER

## Áreas donde ayudar

### Reportar bugs
- Usa EIDOS y encuentra errores
- Abre un Issue describiendo: qué hiciste, qué esperabas, qué pasó
- Incluye logs si es posible

### Mejorar el cerebro de EIDOS
- Añade nodos de conocimiento
- Mejora la identidad y personalidad
- Añade nuevos patrones de reconocimiento

### Nuevas capacidades
- Agentes para la Colony
- Plugins en `skills/plugins/`
- Integraciones con APIs
- Mejoras de UI

### Código
- Optimizaciones de rendimiento
- Corrección de bugs
- Refactorización
- Tests

## Estilo de código
- Python 3.11+
- Sigue el estilo existente
- Usa type hints
- Sin comentarios superfluos
- Nombres descriptivos en español o inglés
